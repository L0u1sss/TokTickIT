## Reflection

The agent was most useful when the request named exact PRs and supplied reviewer feedback, because each recommendation could be checked against concrete lines instead of accepted blindly. Several corrections required judgment rather than copying a reference: retaining the approved ticket-number format, separating Lab 2 requirements from optional production hardening, preserving supported legacy database rows through a corrective migration instead of rewriting applied migration history, treating requester selection as pending until Continue commits a revalidated ID, and keeping attachment upload out of the Create Ticket transaction because the approved contract requires an existing Ticket ID. The first database-test run exposed an assertion that expected a named check even though PostgreSQL rejected the oversized varchar earlier; the test was corrected to verify both enforcement layers. Issue #15 reinforced that a disabled submit button alone is insufficient: the UI reuses one UUID after an uncertain outcome while the server and database return the original Ticket for an identical replay. Issue #16 similarly showed why mocked component checks alone were insufficient: a disposable PostgreSQL fixture was added to prove requester-first counting, stable tie-breaking, combined filters, active-attachment counts, and beyond-last-page behavior against the real schema. The PR #24 follow-up also showed why review comments should be verified against the source of truth: the sort contract was already aligned, while silent URL fallback and indistinguishable metadata failure were genuine gaps that required code, contract, and test changes. Its first hosted follow-up run additionally exposed a cross-runner timing race in the test rather than the implementation; waiting for the observable async call and repeating the focused suite was more reliable than adding arbitrary delays. Issue #17 implementation baseline `68c0beb` passed hosted CI, and documentation-only follow-up `98d8f98` subsequently passed run `33314519404`; Issue #18 supplies the previously deferred real-browser responsive evidence, and implementation baseline `9170d525` passed hosted run `33322281209`. Peer re-review remains pending.

Issue #17 applied the same layered-verification approach to file handling. Service tests established validation, ownership outcomes, and cleanup after metadata failure; HTTP tests established multipart shape, exact-size behavior, safe headers, path handling, and safe errors; and an isolated PostgreSQL fixture with a temporary private directory proved that bytes, metadata, active counts, ownership, downloads, and one-time removal audit fields work together. The UI tests also exposed details that a visual happy path would miss, including Unicode-size boundaries, explicit retry, protected failure states, dialog focus trapping, Escape/restoration, and post-removal focus.

Issue #18 added a separate real-browser layer without inflating it into live E2E. Deterministic network fixtures keep the responsive audit repeatable while Chromium measures actual layout, overflow, focus, and touch-target geometry. The audit found two defects that jsdom could not: the selected requester identity was clipped by a native mobile select, and Ticket Number links in mobile cards were only 21 px high. Both were corrected before the twelve required screenshots were regenerated and reviewed.

Issue #19 keeps that deterministic responsive layer and adds a distinct live layer. The runner refuses an unmarked test database or the same target as development, resets and seeds before every scenario, isolates attachment bytes in a temporary directory, and starts/stops the real server and client automatically. Running each scenario from a fresh database made ownership and failure-state evidence reproducible while still proving real HTTP, persistence, storage, download, soft-removal, session-context, and idempotency behavior. The full local result is server 195/195, client 84/84, responsive 5/5, and live E2E 6/6, with both lint/build suites and Prisma validation passing.
