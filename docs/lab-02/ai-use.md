## Reflection

The agent was most useful when the request named exact PRs and supplied reviewer feedback, because each recommendation could be checked against concrete lines instead of accepted blindly. Several corrections required judgment rather than copying a reference: retaining the approved ticket-number format, separating Lab 2 requirements from optional production hardening, preserving supported legacy database rows through a corrective migration instead of rewriting applied migration history, treating requester selection as pending until Continue commits a revalidated ID, and keeping attachment upload out of the Create Ticket transaction because the approved contract requires an existing Ticket ID. The first database-test run exposed an assertion that expected a named check even though PostgreSQL rejected the oversized varchar earlier; the test was corrected to verify both enforcement layers. Issue #15 reinforced that a disabled submit button alone is insufficient: the UI reuses one UUID after an uncertain outcome while the server and database return the original Ticket for an identical replay. Issue #16 similarly showed why mocked component checks alone were insufficient: a disposable PostgreSQL fixture was added to prove requester-first counting, stable tie-breaking, combined filters, active-attachment counts, and beyond-last-page behavior against the real schema. The PR #24 follow-up also showed why review comments should be verified against the source of truth: the sort contract was already aligned, while silent URL fallback and indistinguishable metadata failure were genuine gaps that required code, contract, and test changes. Its first hosted follow-up run additionally exposed a cross-runner timing race in the test rather than the implementation; waiting for the observable async call and repeating the focused suite was more reliable than adding arbitrary delays. Issue #17 hosted CI is now green on current head `68c0beb`; real-browser responsive evidence and peer re-review remain separate, unfinished gates.

Issue #17 applied the same layered-verification approach to file handling. Service tests established validation, ownership outcomes, and cleanup after metadata failure; HTTP tests established multipart shape, exact-size behavior, safe headers, path handling, and safe errors; and an isolated PostgreSQL fixture with a temporary private directory proved that bytes, metadata, active counts, ownership, downloads, and one-time removal audit fields work together. The UI tests also exposed details that a visual happy path would miss, including Unicode-size boundaries, explicit retry, protected failure states, dialog focus trapping, Escape/restoration, and post-removal focus. Browser screenshots and E2E remain deliberately unclaimed until run.
